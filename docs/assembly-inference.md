# 組み立てを記譜の文法による全体の推論にする — 設計（§0 の (A)、S61）

2026-11-14 に書いた。ROADMAP §0 の (A)。オーナーが (A) を先に本線にすると決めた（同日）。
今の組み立ての地図は 2026-11-14 にコードを読んで作った（下の §1）。行番号はその日のもの。

## 0. なぜ・何を

§0 の診断（HANDOFF 2026-11-14）: 実譜の誤った音の 55〜80% は**検出器が正しい読みに要る記号を見ていた**のに組み立てが違えた。
公平な台では homr との差 7.8 ポイントのうち約 5.7 が「音の高さは合っていて長さ・連符・声部が違う」。

今の組み立ては、**値を 1 つに決めてから**小節の長さで確かめ、合わなければ個別の規則で直す。
直しは規則ごとに別の場所にあり（`UnprintedTriplets`・`MixedThrees`・`RestsBeforeSixteenths`・`LoneTriplets`・`TripletsInThrees`・`HandedThrees`・`Fixes`）、
どれも「その 1 つの直しで小節が合えば採る」。複数の直しの組み合わせや、検出器の確信度と制約の綱引きは表せない。

目標の形: **各記号の読みの候補を確信度つきで残し、小節ごと（必要なら段ごと）に、制約を満たす組み合わせのうち最も確からしいものを選ぶ。**
選んだ答えと次点の差を、そのまま todo の確信度にする。

## 1. 今の組み立て（2026-11-14 の地図）

流れ（`Reader.Read`、Reader.cs:76）:

1. `Detector.Detect` → 0.5 以下の弱い検出を一部のクラスだけ脇の一覧へ（`weakDots`・`weakHeads`・`weakRests` など、:114–155）。**`stem_N`（連桁・旗の本数）と連符の数字には脇の一覧が無い**。
2. `Symbols.Find`（Symbols.cs:695–813）で `Head` に値が書き込まれる: 連桁・旗の本数（`CountBeams` → `DetectedBeams` が検出器の `stem_N` で上書き、拒否権つき）、付点・臨時記号（`Classify`、`Doubts` が臨時記号と付点だけ `HeadAlt` を付ける）、印刷された連符（`FindTuplets` が `Scale`・`Tuplet` を直に書く）。
3. 段ごと: `CheckTimes`（拍子を k·単位で埋まる小節の数の多数決で直す）、分かれた小節・閉じた段末の試し、小節番号の信頼。
4. 小節ごと: `BuildMeasure` → `StaffEvents`（**ここで `Ev.Ticks` が決まる**。:1681 `Dur.Of(basis, Dots)*Scale`）→ `CrossBeams`・`HandedGroups`・`StemsShortOfBeam` → `RestsBeforeSixteenths` → `UnprintedTriplets`（なければ `MixedThrees`）→ `Store` → `Voices.Separate`（**唯一の本当の声部分け**、`Voices.Search`）。
5. 頁: `LoneTriplets`（孤立した小節の数字のない 3 連符を戻す）、`TripletsInThrees`・`HandedThrees`（頁が 3 つずつ進むなら）。
6. `Read` の後: `Fixes.Apply`（Fixes.cs:41–123、長さの直し。**単一の直しを列挙し、ちょうど 1 つが小節を埋めるときだけ採る**。検出器の点数を位置で引き直す、組み立てで唯一の確信度の使い手）。

決定点の性質:

| 決定 | 形 | 使う信号 | 確信度はそこにあるか |
|---|---|---|---|
| 連桁・付点・白い符頭（Symbols） | 貪欲な上書き | インク + 検出器（0.9/0.6 の拒否権） | ある。だがそこで消える（規則の本数は局所の辞書だけ） |
| 印刷された連符（`FindTuplets`） | 数字ごとに貪欲 | 形、`tuplet_N`（0.9） | ある。結果は Head に書かれる |
| `Ev.Ticks`（`StaffEvents`） | Head から一意 | なし | **ない**（`Ev` に点数の欄が無い） |
| `UnprintedTriplets` | 10 組以下の部分集合を列挙（全部 → 大きさ順、`OffGrid` で決着、決まらなければ null） | 声部ごとの小節の長さ、組が拍に乗るか | ない |
| `MixedThrees`・`RestsBeforeSixteenths` | 型 1 つ、埋まれば採る | 小節の長さ | ない |
| `LoneTriplets`・`TripletsInThrees` | 頁の多数決 | 小節の長さ | ない |
| 譜表をまたぐ（`CrossBeams` ほか） | 貪欲な規則 | インク、スラー、小節の長さ | ない |
| 小節線を外す（`IsSplitMeasure`） | 1〜2 通り | 全譜表の小節の長さ | ない |
| 声部（`Voices.Search`） | 探索（DFS + 分枝限定、2 万節点、10 項の辞書式の費用） | 形、符幹、連桁、小節の長さ | ない。**音価は入力で固定** |
| `Fixes` | 単一の直しを列挙 | 検出器の点数の差 | ある |

**食い違い**: 「埋まるか」を調べる `Fills`（:2399）は `Voices.Separate(evs, bar, 0)` で、s = 0 だと `ByStems` の簡易版になる。
`UnprintedTriplets`・`CheckTimes`・`IsSplitMeasure`・`HandedGroups` が調べる声部の模型は、最後の `Store` の `Search` と違う。

不確かさの出口: `Head.Alts` → `Ev.Alts` → `@todo`（臨時記号・付点だけ）、`Fixes.Reading`（埋まらない小節の長さの直し、8 つまで）、`Memo.BarLength` のコメント、Verify。
**音価・連符・声部の代わりの読みはどこにも無い**。

結びつき（組み替えを難しくするもの）:
- 弱い検出は `Symbols.Find` の前に一部のクラスだけ脇へ。`stem_N` と連符の数字の弱いものは消える。
- `Head` の欄をその場で上書き（`Beams`、`Acc = null`、`Scale`/`Tuplet`）。`Fixes` も `h.Dots`/`h.Beams` を書く。
- `Ev` は `res.Bars`・`res.Voices`・`state.Played` で参照を共有し、`Evs`/`Single` の 2 本の一覧を手で揃える（`Resync`）。
- `BuildMeasure` を試しに走らせ、`sym.Unprinted` を手で戻す。
- 小節番号・印刷された番号の信頼・分かれた小節のつなぎが、ループの途中で「埋まるか」を使う。

規模: 関わる関数は約 3,500 行（Reader.cs の約 1,900、Voices.cs 590、Fixes.cs 315、`FindTuplets` 384、`DetectedBeams` 220）。

## 2. 形

### 2.1 候補（仮説）

小節の 1 つの譜表について、次の 3 種の選択を持つ。

1. **音価の候補**（事象ごと）: `{basis, dots}` の組と点数。
   - 出所: 規則の本数（`CountBeams`）と検出器の `stem_N`（0.1 以上の山はどれも）、旗、白い/黒い符頭（`head_filled`/`head_hollow` の両方の点数）、付点（`dot` の点数、0.1 以上）、休符のクラスの点数。
   - 今の `Fixes.Candidates`（Fixes.cs:126–294）が既にこの種の候補を作って点数を引いている。これを土台にする。
2. **連符の候補**（連桁の組・並んだ音の組ごと）: なし / 印刷された N（`tuplet_N` の点数、規則の数字の形）/ 数字のない 3（事前の重み）。
   - 出所: `FindTuplets` の数字（拒んだものも点数つきで残す）と、`UnprintedTriplets` の組の作り方（:1109–1232）。
3. **声部の割り当て**: 今の `Voices.Search` の状態（列ごとの線への割り当て）。

### 2.2 制約

**硬い制約**（破る組み合わせは捨てる）:
- 各声部の長さ = 小節の長さ（弱起・分かれた小節・段末で割れた小節はその長さ。今の `Short`・`IsSplitMeasure` の判定をそのまま入力にする）。
- 連符の組の中の音価の和が組の単位の倍数（3 連符なら 3 つ分）。

**柔らかい制約**（費用）:
- 拍の格子: 連符の組・連桁の組は拍の頭から始まる（今の `OffGrid`・`WorksAs`）。
- 譜表どうしの時刻の一致: 縦に揃った音は同じ時刻（x → 時刻の対応は `Program.Anchors` に既にある）。
- 声部の続き: 今の `Voices.Search` の費用（連桁の穴、線の数、隙間、組の分断、跳躍、符幹の向き）。
- 前後の小節の事前: 頁が 3 つずつ進むなら数字のない 3 連符の重みを上げる（今の `state.InThrees`・`LoneTriplets` の「見えている」）。

### 2.3 点数

費用 = 硬い制約の違反（あれば捨てる）、その次に

    Σ −log p(候補 | 検出器)  +  λ_grid · 拍の格子の違反  +  λ_sync · 時刻の不一致  +  声部の費用  +  事前

p は検出器の点数。S53 の較正表（点数 → 当たりの率）があれば較正した率を使う。規則だけの候補（検出器が見ていない）は固定の小さな確率。
λ は生成譜の台で決め（学習の seed 1 の台で合わせ、seed 7 の check で確かめる。原則 4）、刷りごとに変えない。

### 2.4 探索

小節・譜表ごと。選択の数は小さい: 連符の組は小節に 0〜10、音価の候補が 2 つ以上ある事象は普通 0〜4。

1. 連符の候補と音価の候補の組み合わせを、**長さの硬い制約で枝を刈りながら**深さ優先で並べる（各声部の長さの上限を越えたら刈る）。
2. 残った組み合わせごとに、声部の割り当てを `Voices.Search` で解く（音価が決まれば今のまま使える）。
3. 費用の最小を採り、**次点との差**を残す。

組み合わせが多すぎるとき（節点の予算、今の `Search` と同じ 2 万）は、点数の高い候補から順に上位 k だけを残す（ビーム探索）。
大譜表の時刻の一致は、まず譜表ごとに上位 k を出し、次に譜表の組で選ぶ（2 段）。

### 2.5 出口

- 最良の読みを今の `Ev` に書く（後の段はそのまま動く）。
- 次点との費用の差を確信度にして `Sidecar.Todo` へ（`Fixes.Reading` と同じ道）。次点の読みを `Was`/`Now` に。
- 「硬い制約を満たす組み合わせが無い」小節は、今の `Memo.BarLength` のコメントと length todo のまま。

## 4. 進め方（一歩ずつ、§0 の門に通す）

各歩の終わりに check（頭の規則と `-Detector`）。公平な台・評価台は**歩 3 と歩 5 の終わりだけ**回す（§0）。

| 歩 | 内容 | 門 | 読みが変わるか |
|---|---|---|---|
| 1 | 確信度を運ぶ: `Ev` に音価・連符の点数と候補を持たせる（`Head.Score`、休符の点数、`stem_N` の 0.1 以上の山、拒んだ連符の数字）。弱い `stem_N`・連符の数字を脇の一覧に残す。**済み（2026-11-14）**: `Detector.Faint`（`stem_N`・`tuplet_N` の閾値の下 0.1 まで。`Detect` の一覧には入れない）→ `PageSymbols.Faint`、`Head.RuleBeams`（`DetectedBeams` の前の規則の本数）、`ValueEvidence`（符頭の点数、黒/白、規則の本数、`stem_0..3`、休符 3 クラス、付点）を `Head`・`Rest` → `Ev.Seen`（和音は最大）。`--candidates` が `candidates.tsv`・`candidates-tuplets.tsv`（連符の数字ごとに sure/weak/faint と、読みが採ったか）を書く | 道具（読み手の決定は変えない） | 変わらない（check が全部 same であることを確かめる） |
| 2 | `Fills` の声部の模型を `Search` に揃える。**試した（2026-11-14）、採らない**: s = 0 の道をそのまま `Search` にすると規則の check で WORSE 10（gen-threes2 100 → 98.56 ほか）。守りを 2 つ（全部の線がちょうど小節を埋める、x で右の列は前の列より後に始まる）付けると 0 better・nothing worse で、何も変わらない。原因は `Search` の時刻の模型: 列の順を崩さないことしか求めず x の間隔を見ないので、(a) 長すぎる小節を線を 4 本まで増やし、途中で止まる・途中から始まる線に収める（数字のない 3 連符を 4 分と読んだ 6 つ → `UnprintedTriplets` の「長すぎる」が立たない）、(b) 続けて並ぶ音を同じ時刻に積んで別の声部にする（`b'4 a'4` を 1/4 の 2 声部 → `CheckTimes` が 1/4 を選ぶ）。**1 つの声部の模型にするには、先に `Search` に x を見る時刻の制約を入れる**（下の §5） | 門 2（声部の続き・小節の長さ。どの刷りにも成り立つ） | 変わり得る。生成譜で better が出ることを確かめる |
| 3 | 連符の選択を探索に: 印刷された・数字のない 3 連符の候補を点数つきで並べ、長さの制約と拍の格子で選ぶ。`UnprintedTriplets` の選び方・`MixedThrees` を置き換える | 門 1（`gen-fing`: 運指の数字を連符の数字と取る型、下）と門 2 | 変わる |
| 4 | 音価の選択を探索に: `Fixes` を候補づくりと探索に分け、連符と一緒に選ぶ | 門 2 | 変わる |
| 5 | 譜表どうしの時刻の一致を柔らかい制約に（大譜表の 2 段の選択） | 門 2 | 変わる |
| 6 | todo の確信度を次点との差に | 道具 | 読みは変わらない |

**門 1 の材料（生成器）**: 2026-11-14 に `OmrGen --fingers` を足した（ピアノの版の運指。単音の連なり 1〜6 音に、手のように 1 ずつ動く指番号）。
台 `gen-fing`（全スイート、seed 7、10 曲ずつ、検出器つき）で、今の読み手が運指を連符の数字と取る型が出るかを先に確かめる（HANDOFF）。
数字のない 3 連符（`bare`）は生成器に既にある（`threes`・`mixthrees`・`cross` ほか。`gen-threes`・`gen-mix`・`gen-tupn` などが check にある）。

## 5. 決めていないこと

- λ の合わせ方（生成譜の台で格子探索するか、手で 2〜3 個か）。歩 3 で決める。
- S53 の較正表を先に作るか（点数をそのまま −log に入れると、検出器の作りごとに点数の意味が変わる。S60 の学習し直しの後も同じ λ で動くためには較正が要る）。歩 3 の前に決める。
- 大譜表の 2 段の選択の k。歩 5 で決める。
- `Search` の時刻の制約（歩 2 で分かった）。列の時刻は今「前の列より前でない」だけ。案: x の差が `near`（符頭 1.5 個分）を越える 2 つの列は、後ろが厳しく後の時刻。同じ時刻で列が分かれるのは 2 度・同音でずらした他の声部の音で、`near` の内に収まる。本番の置き方も変わるので、まず生成譜・開発用の台の本番の置き方で、この制約を破っている小節を数えてから入れる。
